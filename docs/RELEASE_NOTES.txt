AutoArm 4.0.2 — Manual tool detachment recovery

A known mounted tool that becomes fully detached can trigger a stopped rebuild
and fresh bare-arm hold, including after a failed swap. All known couplers must
be bare and non-pending, upstream joints must remain attached/functional, the
peer must be current, and full discovery/settling must pass before re-enabling.
The old tool path is revoked. Explicit Stop/Off/SwapCancel and module stops
inhibit recovery. Tool-side commands reacquire released motion leases. Tests
cover manual recovery, failed swaps, stop inhibition, missing/pending parts,
broken upstream joints and isolation in the actual multi-arm host.
External formats and protocol remain unchanged. Update both PB scripts.

Docking, damping and configuration recovery:

Final insertion now pauses at its current line progress when orientation loses
alignment. It no longer commands a return to the insertion start on each angular
tolerance crossing. Measured-motion damping is configurable with PositionDamping
and OrientationDamping, defaulting to 0.2; 0 restores the previous undamped law.
P/I gains are unchanged. Additive manual priority, gravity bias, speed/acceleration
bounds and idle deadbands remain enforced. Delayed velocity-plant tests reduce
peak release overshoot; live SE flex, contact and actuator dynamics are unverified.

Arm and ToolSwap settings are generated even for a headless ToolSwap setup.
Defaults fill missing fields without shadowing global values with generated arm
overrides. A remote On reloads the ToolSwap PB's current public configuration.
Recovery from invalid startup claims input only if no owner was established;
another Arm PB's selection is preserved. Status explains inactive cockpit input.
External formats/protocol are unchanged; existing v4.0 Custom Data can be retained.

Multiple arms and tool quick start:

The Arm PB now hosts up to eight independent arm instances within one shared
instruction budget. Select <arm name> assigns live cockpit input. All commands
accept a final arm target, for example MoveTo(2,0,1,Arm 2), or use the selected
arm when omitted. Stop is scoped; StopAll stops every arm in that PB. Selection
announcements coordinate cockpit ownership across multiple Arm PBs.

Configuration uses [global] plus one section per arm. Local settings override
shared defaults. Global stage preferences validate ordered joint kinds and
parallel/split/rejoin layout, while each arm uses its own geometry and solver.
Home, pose/PID state, faults, equipment, queues and link sessions are per instance.
A ToolSwap PB can serve several hosted arms or several separate Arm PB owners.

Quick start: name each base and one reference block per tool, such as
Arm 1 - Head 1 - Drill and Arm 1 - Head 2 - Welder. Start tools securely merged
onto stands. Their rotor bases and merge blocks are discovered inside facing-
merge-delimited regions. Verified hardware and parked pose are stored on the
named reference block, preserving unrelated Custom Data and surviving ToolSwap
PB Storage loss. No setup mount or teaching is required. Generic PB names are
supported through detected entity-ID pairing. Ambiguous regions/partners refuse.

Use BOTH current scripts. External schemas are Arm [global] Format=7 and ToolSwap
[global] Format=2, protocol AutoArm/5. Older PB Custom Data must be deleted; there
is no migration. Tool marker metadata is AutoArm Tool Format=1.

The build removes inactive Arm/ToolSwap branches and unreferenced helpers from
both readable and compact scripts. The fixed role flag and disabled integral
fallback are absent from generated code. No unreachable-code warnings remain;
the build reports CS0162 diagnostics explicitly. Specialization checks preserve
scopes, expression types, callbacks and initializer/short-circuit effects.

Arm: 99,119 characters, 881 free. ToolSwap: 64,369, 35,631 free. Installed SE API /
C#6 compilation, exact source-method IL after packing and 191,475 simulated
assertions pass. Actual instruction timing and live game physics remain unverified.
