AutoArm 3.0 — Separate ToolSwap PB and ordered motion paths

AutoArm owns the arm, joint state, targets, movement and Home. ToolSwap now runs
in a second PB and owns tool profiles, docking geometry and equipment sequencing.
Only AutoArm writes actuator velocities. ToolSwap sends complete approach and
insertion pose lists; AutoArm executes them and reports waypoint completion.
Retreat is also a path. Optional live anchors follow moving stands. The arm also
accepts world-space pose lists through the public Path Run argument.

Transport uses versioned unicast IGC, scoped peer identities, persistent session
epochs, request sequences and revocable movement generations. Missing valid
communication stops the arm. Attachment changes wait for stopped output; native
part identity, live coupling pose and support observations still gate release.
Stop cancels queued startup/paths. Tool PB restart retains pending-lock recovery.

Install AutoArm_Compact.txt in the arm PB and AutoArm_ToolSwap_Compact.txt in
another PB on the same construct. Configure their exact names in Modules.ToolSwapPB
and Link.ArmPB. Run On on the arm PB once. Successful mounting resumes control;
parking, cancellation and failed operations remain OFF. A simple arm still needs
only the arm PB, with the module name empty.

Configuration is strict: Format 6 for the arm PB, Format 1 for ToolSwap.
Re-enter existing settings in the supplied examples; no migration is included.
Current compact sizes: arm 78,266 characters; ToolSwap 48,330 characters.
C#6/installed SE API, exact token reversal, identical original-source method IL
and 178,559 simulated assertions pass. Live-game physics remains unverified.
Collision geometry/voxel sensing is not implemented in this release.
