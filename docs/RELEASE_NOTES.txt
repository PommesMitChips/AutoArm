AutoArm 4.0 — Multiple arms and tool quick start

The Arm PB now hosts up to eight independent arm instances within one shared
instruction budget. Select <arm name> assigns live cockpit input. All commands
accept a final arm target, for example MoveTo(2,0,1,Arm 2), or use the selected
arm when omitted. Stop is scoped; StopAll stops every arm in that PB. Selection
announcements coordinate cockpit ownership across multiple Arm PBs.

Configuration uses [global] plus one section per arm. Local settings override
shared defaults. Global stage preferences validate ordered joint kinds and
parallel/split/rejoin layout, while each arm uses its own geometry and solver.
Home, pose/PID state, faults, equipment, queues and link sessions are per instance.
A ToolSwap PB can serve several hosted arms or several separate Arm PB owners.

Quick start: name each base and one reference block per tool, such as
Arm 1 - Head 1 - Drill and Arm 1 - Head 2 - Welder. Start tools securely merged
onto stands. Their rotor bases and merge blocks are discovered inside facing-
merge-delimited regions. Verified hardware and parked pose are stored on the
named reference block, preserving unrelated Custom Data and surviving ToolSwap
PB Storage loss. No setup mount or teaching is required. Generic PB names are
supported through detected entity-ID pairing. Ambiguous regions/partners refuse.

Use BOTH current scripts. External schemas are Arm [global] Format=7 and ToolSwap
[global] Format=2, protocol AutoArm/5. Older PB Custom Data must be deleted; there
is no migration. Tool marker metadata is AutoArm Tool Format=1.

Shared host role checks and integral unwind expressions no longer produce
unreachable-code warnings. The build reports CS0162 diagnostics explicitly.

Arm: 99,315 characters, 685 free. ToolSwap: 68,173, 31,827 free. Installed SE API /
C#6 compilation, exact source-method IL after packing and 179,770 simulated
assertions pass. Actual instruction timing and live game physics remain unverified.
