AutoArm 2.8.1 — One-shot startup and automatic tool-control resume

On now reloads current configuration, discovers the arm, scans configured tools
and enables manual control after stopped setup succeeds. It works during the
initial scan and on fresh bare arms. Toggle/OnOff follow the same startup path.
Successful tool pickup/swapping resumes manual control at the mounted tool's
current pose. Selecting an already mounted tool also enables control. Parking,
diagnostic scans, failed operations and cancellations remain OFF. Stop cancels
deferred startup; On cannot interrupt an active automatic swap.

Custom Data remains Format 5. Existing v2.8 settings need no format changes.

C#6/installed SE API compilation, exact token reversal, identical method IL and
178,062 simulated assertions pass. Live game physics remains unverified.

AutoArm 2.8 — Automatic bare endpoint discovery

Name the arm Base and configure the tools' markers, rotor bases and merges.
An arm-side ToolMount name, reference camera and ArmTip offset are unnecessary.
The script follows moving grids and finds a single loose rotor part, including
one directly on the final hinge's moving head. That part is the bare-arm focus;
a mounted tool uses its configured marker. Startup rescans without teaching or
saved coupler geometry. Ordinary arm joints remain pistons, rotors and hinges.

Detection excludes known attached tops and refuses multiple parts, unsupported
shapes or ambiguous mounting faces. Native pivot/axis alignment permits arbitrary
rotor azimuth during first acquisition. The selected rotor's angle limits must
be unlimited for that acquisition; Rotor Lock is temporarily released and restored
only after verification. Actual part cell, family, finite axis, moving grid and
reciprocal base precede the existing two-observation pose/support release gate.
Interrupted lock intent is journaled and explicitly reconciled while supported.

Custom Data uses Format 5. Incompatible formats are rejected: keep settings you
want to re-enter, delete Custom Data and copy the current example or Reload.
No migration is included. Instructions and boilerplate setup banners are removed.
README is the setup/command guide. ToolNN.Mount still names each tool's rotor base.

Packing additionally fuses equivalent adjacent fields, unqualifies imported types
and converts single-return methods, preserving original-source method IL.
