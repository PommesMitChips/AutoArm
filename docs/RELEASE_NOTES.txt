AutoArm 4.0.7 — Merge while approaching, stop on actual capture

Parking now enables the selected tool's head merges during approach, after the
Arm PB acknowledges the path with capture monitoring installed. It does not
wait for measured vibration to die away before allowing the merge to happen.
The parking clearance waypoint also uses geometric admission without a quiet
velocity prerequisite. Pickup and generic path admission retain their policies.

The Arm PB checks safety merges of the previously mounted tool before every
path solve and topology validation. Any connection immediately zeros drives,
cancels the path and pauses stale topology. This does not depend on the next
ToolSwap callback, endpoint settling, or a timeout.

ToolSwap independently observes capture and waits stopped for all intended
reciprocal stand pairs. Partial/unproven support cannot detach the rotor. The
existing continuous connection proofs, stopped mutation acknowledgements,
rebuild and confirmed resume remain. Wrong upstream attachments still fail.

Update BOTH scripts, keep existing Custom Data, and run On once. Formats and
protocol are unchanged. Capture is optional metadata on the scoped ToolSwap
lease; other planner paths do not enable this behavior. Manual control/PID
is unchanged. The final capture-gap fallback and saved mating pose remain.

Validation: C#6 against installed SE interfaces, source specialization, committed
baseline packing with exact token/compilation/method-IL checks, and 194,723
standard simulated assertions. Capture tests connect while the path is moving
and filtered velocity is above old thresholds, run the Arm alone to prove local
stopping, refuse partial/unproven support, and complete automatic swap/resume.
The reviewed repetition/namespace packer also passes compact-host tests via the
integrated test adapter (194,866 total assertions). Live SE capture/contact
still requires confirmation. No features or diagnostics were removed.

Arm: 90,452 characters, 9,548 free. ToolSwap: 57,716, 42,284 free.
