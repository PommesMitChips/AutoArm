# Development

Development requires Windows, the .NET 10 SDK, the .NET Framework reference assemblies, and a local Space Engineers installation. Game assemblies and model assets are not included.

From this repository:

```powershell
.\tools\Build-AutoArm.ps1 -Test
```

For a nondefault game location:

```powershell
.\tools\Build-AutoArm.ps1 -GameBin 'D:\SteamLibrary\steamapps\common\SpaceEngineers\Bin64' -Test
```

Edit the fragments in `src/`. The build regenerates the source and compact files for both the arm and ToolSwap PBs, checks C# 6 against installed SE APIs and after the installed game memory-safe/type-safety rewrite, verifies token round-trip and identical method IL, and runs the simulated PB harness. Tests also regenerate `examples/CustomData.ini`. [`src/AutoArm.Seam.md`](../src/AutoArm.Seam.md) describes the implementation boundaries.

The current compact scripts contain 93,047 UTF-16 characters (arm; 6,953 free), 57,907 (ToolSwap; 42,093 free) and 18,543 (Collision; 81,457 free). Each PB has its own 100,000-character allowance. UTF-8 file bytes are not the PB character count. Velocity and acceleration settings are not physical momentum measurements; torque/force, travel limits and game physics determine achievable motion.

See [MODULES.md](MODULES.md) for the transport and path contract. AutoArm owns velocities, targets, topology and Home; ToolSwap owns docking geometry and equipment operations. Shared math and message encoding are built into both scripts from one source. ArmTipInfo holds only the received frame/local pose; ToolSwap keeps live or inferred rotor identity in ToolTopInfo. The Arm endpoint does not enumerate an unused inventory. ToolSwap geometry does not carry the arm solver or its joint-control state. Optional Collision PB supplies clearance guidance through the Safety role; see COLLISION.md.

Packing first uses one-character BMP identifiers for script-owned members and scoped locals, preserves enum/API values, shortens numeric and string spelling only when exact values match, and verifies token reversal plus identical method IL. A second pass measures each repeated string, external method and property against the complete cost of its constant or forwarding helper; it keeps only smaller, compilable output and proves exact syntax expansion back to the first-stage program. Mutable struct receivers, ref/out, generic and extension methods are excluded. A small PB entry point forwards to an implementation class inside a namespace, allowing C# 6 using aliases for safe repeated external types without changing type identity. Collection types, StringBuilder and types containing them are excluded recursively: the game can construct nonexistent MemorySafe alias names or silently skip collection instrumentation. Each type alias is measured separately, and the combined layout must save space after all entry-point and live game-context forwarding costs. Expanding aliases and removing the forwarding facade must recover identical implementation IL. Constructor, Main, Save, Echo, Storage and the actual game API objects are forwarded; the implementation does not create a second MyGridProgram. nameof retains its original constant value. Production targets C# 6; newer pattern matching is not used. Readable source shares pose targets, capture/reset, angle wrapping, finite checks and frame conversion; saved Home remains native joint-space control.
Declaration compression also removes redundant private modifiers and uses inferred local/array types only when Roslyn proves identical types. Final method IL is compared against the original readable source compilation. Control shares task-matrix formation and scalar component/bound-hit logic; numerical operation order and native Home routes are retained. Actual game instruction cost remains unprofiled.

Tool discovery starts from the Base marker, excludes the hull and configured tool couplers, and incrementally scans reachable moving grids. Connected top parts are excluded from hidden-cell candidates. A single 1-cell or 3x2x3 rotor-shaped region and one plausible mounting face determine pivot and signed axis. Unknown part identity and azimuth are confirmed only after attachment; first acquisition requires unlimited rotor limits and temporarily unlocks/restores Rotor Lock. Multiple candidates or ambiguous faces refuse. New graph and postprocessing work has inventory/link bounds and budget checks. Coupler pose storage is unnecessary; startup rescans instead. External Arm Format 7 and ToolSwap Format 2 omit Instructions and ArmTip. Automatic profiles require only numbered tool reference markers; bases and support merges are detected and persisted on the marker.

Further packing unqualifies imported type names, converts single-return methods to C#6 expression bodies and fuses adjacent equivalent field declarations while preserving initializer/metadata order. Exact original-source IL validation remains required for this first packing stage.

Tool revision tests additionally verify arm-default travel above 1 m/s despite lower manual correction caps, slow line entry, no premature endpoint acknowledgement at low speed, preserved parked pose after a quarter-turn and ToolSwap restart, declared topology pauses and automatic activation after rebuild. Protocol v5 carries the existing per-waypoint policies and expected transitions in independent arm-addressed sessions; external configurations use global Format 7/2.

Optional `ArmServices` peers route by authorized sender ID before the existing ToolSwap handler. They use independent epochs, sequences and replies, plus a revocable arm revision for path ownership. The original specialized ToolSwap lease remains exclusive. Tests cover four concurrent peer roles, measured native-solver path completion, planner contention, invalid-path atomicity, unauthorized stop attempts, owner restart/watchdog, stale/cross-arm messages, one planner independently leasing two Arm PBs, and a third PB observing ToolSwap without disrupting resume. Planning and monitoring can run in other PB budgets; numerical joint solving stays local.

Active validation precomputes unowned edges, leaves markers/endpoint checks live, and defers owned edge/sync checks to the mandatory group Refresh before commit. Test getter counters confirm one attachment and one Angle read per singleton on a ten-rotary active pass; this is an API-call count, not measured game instruction time. Last-stage disconnect, parallel desynchronization and Home disconnect still stop in the same pass. Full snapshot cadence and explicit full validation are unchanged.

Saved tool preferences are loaded atomically and pruned only after successful stopped discovery. Missing/closed/wrong-family identities are removed; surviving parked or nonfunctional actuators are kept. Cleanup does no per-tick enumeration, stages removals before writing, respects the instruction reserve and preserves unrelated Storage. Tests cover cold-load cleanup, deleted IDs, parked retention, low-budget refusal and failed-discovery preservation.

The v4.0 build assembles one ArmCore implementation behind a multi-arm host. The build performs documented adapter substitutions for constructor/host access, virtual Custom Data/Storage/frequency/elapsed time, per-instance inboxes and protocol v5. A Roslyn specialization pass removes constant-disabled branches, folds role-dependent expressions and repeatedly removes unreferenced methods, properties and fields. Entry points, overrides, interface implementations, callbacks and effectful initializers are retained. Branch scopes, expression precedence and built-in conversions are preserved; fixture checks execute both roles before and after specialization. The resulting readable source is the input to the same C#6, token-reversal and exact-method-IL packing gates. Ignored intermediate engine sources let the existing 179,678-assertion algorithm suite run independently; the new host suite additionally runs the actual generated Arm and ToolSwap programs.

Host tests verify selected-only pilot input, commands with an explicit or omitted arm target, unknown-target refusal, global setting/weight inheritance, local overrides, equal layout with different physical lengths, mismatched kinds/parallel counts, independent Home/restart state, cross-PB input selection, one helper's independent arm sessions, and a shared ToolSwap PB serving one multi-arm owner or two separate owners. Automatic setup tests name only bases and tool markers, leave mounts/merges/PBs generically named, start all tools parked, perform pickup/return and resume, preserve opaque head Custom Data, and recover mounted tools after clearing the ToolSwap PB's Storage. Marker-stored hardware and park pose are validated by fresh region/native checks.

Shared templates cover the arm body. Coupling and downstream tool joints remain independently discovered, preventing a bare/mounted transition from invalidating a common body template. Multiple arms share the PB instruction allowance; native instruction cost and real merge timing still need in-game testing. Without a configured Safety peer the arm runs without collision avoidance.

Compression decisions are written beside the name maps as `tools/ScriptPack/obj/*_Compact.names.compression.json`, including rejected candidates and net UTF-16 savings. Compression fixtures exercise escaped strings, overloads, optional conversions, nested calls, argument side effects, null receivers, rejection of costly aliases and namespace/nameof expansion. `Build-AutoArm.ps1 -Test` also repeats the host integration suite against the actual compact programs, using the generated name maps only for test inspection. Forwarding helpers add method calls; native game instruction costs and live execution still require game verification. The unconditional build gate in tools/PBCompileChecks loads the installed TypeSafetyAndBlockRewriter with the game's own Roslyn version in a separate process, rewrites each source/compact artifact with memory-safe types enabled, and emits the result against installed interfaces. Negative fixtures reproduce the original StringBuilder alias error and silent closed-collection bypass; positive fixtures require native List, Dictionary, HashSet, Queue and StringBuilder instrumentation. This gate covers the game type-rewriting stage; it does not execute the full PB whitelist/performance-injection pipeline or the live physics engine.

Collision architecture, envelopes and limits are documented in [COLLISION.md](COLLISION.md). Full builds assemble, pack and run installed SE rewriting for all three PBs. The host tests also execute the actual compact Collision service. A separate v4.0.9 comparison with Safety absent matches native output exactly for 1,800 frozen-geometry mixed/parallel control ticks. Use Build-AutoArm.ps1 -SourceOnly for rapid readable-source compilation and focused ArmTests --collision iteration; full -Test always requires packed artifacts.
