# Development

Collision v5.0.5 corrects self-contact at directly mounted vanilla joint collars. A piston/rotor/hinge top that directly supports the next rotor/hinge base is treated as part of that joint's interface against its exact attached head. Recognition requires the installed vanilla envelopes, live confirmed attachments on both joints, opposite primary mounting faces, direct one-cell placement and a head remaining at the coupling. Displaced, indirect, unsupported, changed-model and unrelated-arm contacts retain collision checks. This is an explicit assembly-interface policy, not a general assertion that adjacent links cannot collide. Actuator bodies and other cells are not exempted.

Other actuator pairs owned by the same authenticated arm now use validated vanilla model envelopes instead of treating their entire allocation cells as solid. These non-interface pairs retain the full configured clearance. Armour, drills/tools, other arms and unrelated hull geometry retain their occupied-cell bounds. Unknown/changed models fall back to cells. The existing animated-piston/model limitations still apply.

Packing first uses one-character BMP identifiers for script-owned members and scoped locals, preserves enum/API values, shortens numeric and string spelling only when exact values match, and verifies token reversal plus identical method IL. A second pass measures each repeated string, external method and property against the complete cost of its constant or forwarding helper; it keeps only smaller, compilable output and proves exact syntax expansion back to the first-stage program. Mutable struct receivers, ref/out, generic and extension methods are excluded. A small PB entry point forwards to an implementation class inside a namespace, allowing C# 6 using aliases for safe repeated external types without changing type identity. Collection types, StringBuilder and types containing them are excluded recursively: the game can construct nonexistent MemorySafe alias names or silently skip collection instrumentation. Each type alias is measured separately, and the combined layout must save space after all entry-point and live game-context forwarding costs. Expanding aliases and removing the forwarding facade must recover identical implementation IL. Constructor, Main, Save, Echo, Storage and the actual game API objects are forwarded; the implementation does not create a second MyGridProgram. nameof retains its original constant value. Production targets C# 6; newer pattern matching is not used. Readable source shares pose targets, capture/reset, angle wrapping, finite checks and frame conversion; saved Home remains native joint-space control.
Declaration compression also removes redundant private modifiers and uses inferred local/array types only when Roslyn proves identical types. Final method IL is compared against the original readable source compilation. Control shares task-matrix formation and scalar component/bound-hit logic; numerical operation order and native Home routes are retained. Actual game instruction cost remains unprofiled.

Tool discovery starts from the Base marker, excludes the hull and configured tool couplers, and incrementally scans reachable moving grids. Connected top parts are excluded from hidden-cell candidates. A single 1-cell or 3x2x3 rotor-shaped region and one plausible mounting face determine pivot and signed axis. Unknown part identity and azimuth are confirmed only after attachment; first acquisition requires unlimited rotor limits and temporarily unlocks/restores Rotor Lock. Multiple candidates or ambiguous faces refuse. New graph and postprocessing work has inventory/link bounds and budget checks. Coupler pose storage is unnecessary; startup rescans instead. External Arm Format 7 and ToolSwap Format 2 omit Instructions and ArmTip. Automatic profiles require only numbered tool reference markers; bases and support merges are detected and persisted on the marker.

Further packing unqualifies imported type names, converts single-return methods to C#6 expression bodies and fuses adjacent equivalent field declarations while preserving initializer/metadata order. Exact original-source IL validation remains required for this first packing stage.
