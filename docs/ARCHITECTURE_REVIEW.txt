Prioritized structural opportunities (NOT demonstrated savings):

1. Public/private configuration representation. Host.InternalConfig projects
   public Format 7/2 into private Format 6/1; CaptureDefaults reverses the projection.
   Combined reviewed packed footprint: 1,552 characters; private validators: 764.
   A replacement still needs inheritance, validation and exact public values.
2. Stage-weight paths. ArmFacade's public table and AutoConfig's private
   name/identity table overlap. AutoConfig footprint: 4,786; only part is redundant.
   Keep physical identities, parked preferences, stopped topology handling and
   global/arm overrides. This is the strongest deeper consolidation candidate.
3. Startup stopping. Host.StopSaved plus ArmCore.ZeroSavedDrives footprint: 1,120.
   Coverage, validation, exception handling and timing differ. Any shared helper
   must retain both recovery guarantees and should be judged by measured net size.
4. Parse routed IGC once. Preserve sender/construct checks, arm and session
   isolation, replay protection, leases and watchdogs. Runtime benefit is unmeasured.
5. Replace textual host adaptation with an explicit context boundary only if
   it improves maintainability without unacceptable packed growth.

Evidence against deleting major algorithms as duplication: ToolSwap's topology
descriptor footprint is 66 characters; Arm's real topology engine is 15,120.
The ToolSwap script does not contain the arm solver, and all hosted arms share
one compiled ArmCore implementation. Similar acknowledgement logic does not
justify merging distinct ToolSwap and service ownership machines.
