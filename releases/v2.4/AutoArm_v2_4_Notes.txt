DEFAULTS IN CUSTOM DATA
[Config]
MovementMode=HEAD
ReadMouse=false
MouseSensitivity=0.025

MovementMode accepts HEAD, HRZ or VRT (case insensitive). Edit it and Reload,
then Check/On. Reload/Rescan or recompiling restore all Config defaults.
Mode HEAD / Mode HRZ / Mode VRT change the live view without stopping or
recapturing the held head pose. MovementMode and ControlMode are aliases for Mode.
ReadMouse On / Off / Toggle controls optional mouse input at runtime.

MOVEMENT
The active cockpit/remote controller supplies the game's translation, rotation
and roll indicators. It can be anywhere on the same mechanically connected ship,
including an arm/head grid or another ship module. A cockpit name is not required;
Arm Controller can simply be the name you give your operating cockpit.

          W / S                       A / D              C / Space
HEAD      Head Forward / Back         Head Left / Right  Head Down / Up
HRZ       Cockpit Forward / Back      Cockpit Left/Right Cockpit Down / Up
VRT       Cockpit screen Up / Down    Cockpit Left/Right Into / Out of view

In VRT, C is cockpit Forward (into the view), Space is cockpit Backward
(toward the viewer). Thus top and bottom views both follow their own camera axes.
Keyboard diagonals are normalized, so diagonal movement is not faster.
Keys above assume the usual game bindings; actual input follows your game settings.

HEAD is suitable for a camera aligned with the marked Head block's orientation.
HRZ is the side/excavator view; VRT is the top/bottom/crane view. Both use the
cockpit you are actively piloting. Switching cockpits changes the reference frame;
switch Mode too when changing between horizontal and vertical views.
After leaving a cockpit, cached input is immediately ignored. Finding another
active cockpit can take up to ten polls; direction toolbar commands query at once.
If several controllers are active, the established cached/deterministic selection
policy applies. The script cannot identify which human operator you intended.

ORIENTATION
Translation keeps the captured Head orientation target in all modes, including
when the solver needs correction under gravity or cannot achieve the requested
motion. Switching modes keeps the position and orientation targets unchanged.
Holding still retains the improved load compensation from 2.3. Actual accuracy
depends on configured tolerances, actuator limits, torque and available motion.

Q/E always rolls around actual Head Forward, independently of the movement mode
and ReadMouse. Positive game RollIndicator retains its prior sign convention.
Optional mouse input rotates about the current view's Up/Right axes: Head view in
HEAD, active cockpit view in HRZ/VRT. VRT's translation remapping does not change
the mouse's camera axes. MouseSensitivity scales RotationIndicator; the default
0.025 is 1/40. Combined mouse plus roll is capped by HeadTurnSpeed.
ReadKeyboard and ReadRoll remain independent switches.

NAMED TOOLBAR ACTIONS
Configure a programmable-block Run action with its text argument:
  PitchUp    Back      PitchDown
  Left       Down      Right
  YawLeft    Forward   YawRight
Additional actions: Up, RollLeft, RollRight, Hold, Stop, On, Toggle,
Mode HEAD, Mode HRZ, Mode VRT, ReadMouse Toggle, and other listed commands.
There are no configurable Bind1..Bind9 values in Custom Data.
The previous numeric 1..9 arguments remain fixed compatibility aliases for the
nine actions above, in that order. Prior custom numeric remappings are removed;
replace any such toolbar entries with the desired action's name.

Forward/Back/Left/Right/Up/Down orient the Head, rather than translating it.
Use WASD/C/Space for translation. Face <direction> is the equivalent explicit form.
In HRZ/VRT these presets use raw cockpit cardinal directions. In a crane view,
Forward therefore points into the view even though W moves in the screen plane.
HEAD presets retain the previous Base-frame directions.
YawLeft/Right rotate about cockpit Up in HRZ/VRT (Base Up in HEAD).
PitchUp/Down rotate about cockpit Right in HRZ/VRT (target Head Right in HEAD).
RollLeft/Right and Step Roll always rotate about target Head Forward.
Step Yaw|Pitch|Roll <degrees> and Yaw/Pitch/Roll <degrees> remain available.
HRZ/VRT direction commands require an active cockpit; they never substitute Base
axes for a missing cockpit. Invalid controller axes/input stop motion safely.

GoHome still stops on pilot takeover and requires On to resume. Takeover now checks
enabled raw input, including mouse, so HeadSpeed=0 or canceling mouse/roll vectors
cannot hide an operator action.
