INSTALL
Stop the previous script, paste this release, and keep existing Custom Data.
Startup migrates recognizable older discovery configuration into:
  [AutoArm]       arm name and format version
  [Instructions] setup, commands and permitted toolbar actions
  [Config]       speeds, caps, hold tuning, input flags, bindings and actuator table
Existing actuator preferences migrate by exact physical identity, not position
or block name. Matching saved homes migrate too. Run Version to verify 2.3,
review the generated Config, then Check and On.

EDITING
Settings include units and accepted ranges. HeadSpeed is m/s; HeadTurnSpeed is
deg/s. JointSpeed is RPM, PistonSpeed is m/s. JointAcceleration is RPM/s and
PistonAcceleration is m/s^2. These are velocity and acceleration limits, not a
measurement or control of physical momentum.

Bind1..Bind9 choose single actions for PB toolbar Run arguments 1..9. Set a Bind
to None to disable it. These settings do not change the game's keyboard map.
Translation and roll use Space Engineers ship-controller bindings when enabled.
Direct commands such as Speed are temporary; Config values are reapplied by
Reload/Rescan or recompile. The Bindings command shows the active mapping.

Actuators is a four-column multiline table:
  Name | Kind | Translation | Orientation
Edit only the two weights (0..10). Weights guide solver allocation; they are not
motion percentages. Parallel members share a row. The ordinal prefix distinguishes
repeated names. Pipes/newlines in block names are sanitized for display.
The leading | on each continuation line is required by the game's INI format.

After edits run Reload. It stops the arm, validates all values, and waits for
stable setup; Check and On resume motion. Invalid data is left untouched.
Info, Joints and Check hold the physical IDs/geometry outside Custom Data.

The table's identities live in PB Storage, alongside Home. This keeps visible
configuration clear while preserving weights across reloads, rescans and saves.
If copying the script/config into another PB, blank the Actuators value before
Reload so it discovers and generates defaults for that PB. A populated table
without its matching saved identity cache is refused; names alone cannot safely
identify joints. Blanking Actuators also intentionally resets all group weights.
Opaque older Storage is retained verbatim in the INI end content.

SUSTAINED-LOAD HOLD
The controller now retains learned compensation inside its successful hold
deadband. It previously decayed this compensation, allowing drift to return.
It also distinguishes solver damping from loss caused by actuator bounds; normal
damping no longer prevents compensation from learning.

PositionIntegralGain defaults to 0.5, OrientationIntegralGain to 0.25 (1/s^2).
PositionIntegralCap defaults to 0.2 m/s; OrientationIntegralCap to 5 deg/s.
Bias is additionally limited by correction caps (and angular turn speed).
Zero gain disables that channel's learning. Off, Hold and fresh On reset learned
bias, so compensation must build again after recapture. Idle orientation tolerance
remains 3 degrees; reduce OrientationTolerance for a tighter angular hold.

Learned correction remains additive to live input. Opposing correction is limited
to 50% of pilot demand for translation AND roll; perpendicular correction remains.
Motor torque/force and physics still determine whether an actual arm can resist
gravity. The script does not raise motor Torque or BrakingTorque automatically.
Bounded integral compensation cannot overcome inadequate mechanical authority.
Errors outside capture range unwind bias; unreachable task directions can retain
bounded bias, so this is not a gravity feed-forward model or collision controller.

PREVIOUS FEATURES
Zero-time commands remain supported. Known connections are checked every active
pass, with full inventory snapshots every 30 active passes and explicit checks.
Unknown additions can take up to 30 active passes to detect. Routine display
formatting remains about 4 Hz, with cached Echo replay every invocation.
PivotProbe remains passive and leaves the control pivot unchanged. Real in-game
pivot measurements are still required before selecting another pivot model.
